# CIVILIZATION Specialist Workflow｜Quick Start

## 新项目怎么开始

1. 把客户 Brief / 会议纪要放进项目文件夹。
2. 加载 **Project Hub v1.11**。
3. 如果已知距上次 Skill 版本检查超过 **7 天**、版本来源不明，或你想确认最新版，并且当前环境可以访问 GitHub，先让 Project Hub 按 **VERSION / UPDATE PROTOCOL** 检查仓库 main branch。
4. 对它说：

> 这是一个新项目。请建立 PROJECT_STATE.md，判断当前阶段，并告诉我下一步应该调用哪个 Specialist。不要做专业分析。

## 一个原则

> **一个 Skill 解决一个专业问题，并把它解决透；不追求大而全。**

当前是 **1 Hub + 4 个专业 Specialist**：

- Brief Discovery Specialist
- Creative Exploration Specialist
- Product Innovation Specialist
- Proposal Development Specialist

## 怎么路由

```text
刚收到 Brief、需要先理解市场和品牌，或问题尚未解清楚
→ Brief Discovery Specialist v1.26

问题已清楚，需要传播 Idea
→ Creative Exploration Specialist

问题已清楚，需要产品 / SKU / 配方 / 风味 / 功能等创新
→ Product Innovation Specialist v1.6

已有 Strategy / Idea / Innovation Direction，需要形成完整提案文件
→ Proposal Development Specialist v1.15
```

## 不必每次从第一轮开始

**FULL EXPLORE**：新项目且方向未明，走完整专业SOP。  
**LOCAL DEEPEN**：已有策略或产品方向，继承当前判断只研究眼前缺口。  
**DIRECT REVIEW / EXECUTION**：只修改一页PPT、一张数据表或一个产品概念时，先交付具体结果；有实质冲突才建议Reopen。

数据诊断、产品拆解、Consumer Value Expansion、产品/概念/表达Option区分和交付QA按需调用，不把这些检查变成用户必须填写的问卷。

## 推荐不等于选择

AI 可以主动推荐最值得推进的方向，也可以在没有明确否决项时条件性继续做深；但只有用户 / 团队 / 客户明确选择，或上游已经可靠记录为已选时，才写入 `SELECTED DIRECTIONS`。

> **“继续” ≠ “我选择这个方向”。**

## Brief Discovery Specialist v1.26｜先研究现实，再分析 Brief

若 Brief 引用了外部模型或专业术语，先核实定义及适用边界，不把 AI 自创解释当成原始理论；只查与决策有关的概念。

```text
市场发展、竞争趋势、消费者行为与品牌背景/资产
  ↓
客户真实需求、为什么现在提出 Brief、想改变什么
  ↓
现实与客户判断/策略/Offer/目标用户等的相关落差
  ↓
Problem Landscape → Strategy / Opportunity Territory
  ↓
品牌策略类任务按需进入 Brand Logic Bridge
Human Spark → Brand Belief → Brand Role → Product / Offering Truth → Competitive Contrast → Positioning Difference
```

四个外部视角是基础功课，但不要求固定报告篇幅；只有在项目真实涉及且影响判断时，才深挖产品计划、既定主张或历史技术资产，**不默认存在未来12个月产品计划**。Brand Restage / Repositioning / Brand Platform / Proposition 类任务即使客户没有现成定位，也要主动形成有证据边界的 Working Brand Logic。

直接使用：

> 请按 Brief Discovery Specialist v1.26 开始。先独立研究市场、竞争、消费者与品牌资产，再分析我的 Brief、客户动机和现实差距。品牌策略类任务请继续推到 Human Spark、Brand Logic 与 Positioning Difference；不要先让我填问卷，也不要提前生成 Idea / IMC。

## Creative Exploration Specialist v3.0

**默认任务是解决真实创意问题，而不是把 Human Insight / Creative Spark 逐级包装成 Idea。**

```text
ORIGINAL PROBLEM + REAL MATERIALS / CONSTRAINTS
  ↓
OPEN CREATIVE LEAP｜开放产生具体、真正不同的 Idea Seed
  ↓
FIRST CUT｜先看惊喜、问题相关性与品牌归属
  ↓
REALITY TEST｜再核实竞品、品牌事实、受众与执行条件
  ↓
SELECTION / IDEA DEVELOPMENT｜选中后做实，需要时才扩展 IMC
```

**IDEA FIRST（默认）**：用户要 Big Idea、Activation、广告内容或品牌创意时，直接给创意种子，先让人能看到「这件事是什么」。第一次停在 Idea Seed 校准，而非 Case Landscape / Spark Calibration。

**CASE RESEARCH / RESEARCH ATLAS（按需）**：用户要系统案例研究 / Casebook 时，完成真实来源、实际执行视觉、可追溯链接与文件 QA；此任务可以独立完成，不强制转入 Idea。

**IDEA SEED DEVELOPMENT（直达）**：已选择的 Idea 直接深化。若核心平庸，回到 OPEN CREATIVE LEAP 重新发明；不能用长篇策略辩护或 KOL / Social / Activation 层级救活普通 Idea。

Human Spark、Human Insight、Creative Spark、案例均是**可选参考**，必须保留真实证据状态；不作为必须走完的创意推导环节。用户只说「继续」不等于明确 Selection，AI 可以条件性推进。

## 四个 Specialist 的语言控制

Brief、Creative、Product Innovation、Proposal 的用户可见输出共同参考 [LANGUAGE_CONTROL.md](./LANGUAGE_CONTROL.md)：

- tension 保留英文，不为了策略感硬翻成更虚的词；
- 具体行为优先于抽象名词；
- 不确定就直接说不知道；
- 少用 AI 套话和咨询黑话；
- 框架留在底层，不把框架感全部倒给用户或客户。

## Product Innovation Specialist v1.6

选产品方向时轻量核对承诺、实际使用体验、产品事实与可行性；不以尚缺研发证明自动否决有潜力的方向。跨职能信号只写入 Hub 的 `CROSS-WORKSTREAM SIGNALS`。

```text
INNOVATION CASE LANDSCAPE
  ↓
SPARK CALIBRATION
  ↓
FOLLOW THE SPARK
  ↓
KEEP / HOLD / DROP
  ↓
INNOVATION TRANSLATION
  ↓
TESTABLE HYPOTHESIS / PROOF NEEDED
```

每个重要案例强制区分：

- **RESULT SCOPE**：SKU / PLATFORM / BRAND / CATEGORY
- **EVIDENCE QUALITY**：A / B / C / D / E
- **CAUSALITY CHECK**：结果是否真能归因于创新
- **CLAIM-SPECIFIC STATUS**：同一份证据对不同 Claim 可对应不同 STATUS
- **SOURCE AUDIT**：正式案例保留来源、日期、Verification、能证明 / 不能证明什么

不自动生成 Campaign / IMC。用户可见输出先把产品机会讲清楚：谁为什么会想买、产品到底改了什么、吃到 / 用到时有什么不同，再补 Consumer Job、Innovation Mechanism 和证据。

## HOLD / DROP

- **HOLD**：有价值但当前不优先。
- **DROP / SUPERSEDED**：停止投入或已被替代。

下游不得为了“都用上”而自动复活。

## Review 后怎么办

- Solution 成立 → **KEEP**
- 当前方向成立，只缺局部连接 → **REPAIR**
- 需要重新打开传播 Idea → **CREATIVE REOPEN**
- 需要重新打开产品创新 → **INNOVATION REOPEN**
- 问题定义 / 关键前提改变 → **BRIEF REOPEN**

## Product Innovation 之后不一定去 Proposal

可以直接进入：

- R&D / technical validation
- Consumer / prototype test
- Business / channel validation

只有需要把已确认方向发展成提案文件时才进入 Proposal Development Specialist。

产品方向基本锁定、并明确需要传播探索时，再进入 Creative Exploration Specialist。

## Proposal 的证据语言

> **Evidence status must survive rewriting.**

即使进入 PPT 标题或客户文案，WORKING HYPOTHESIS 也不能被改写成确定事实。语言强度必须跟着证据状态走，但不要求把 STATUS 标签直接展示给客户。

## 没有文件读写能力怎么办

每个 Specialist 结束时输出：

> PROJECT STATE BLOCK

复制给下一位 Agent 即可。

## 一句话记住

> **Hub 管协议与交接；Brief 管问题和 Brand Logic；Creative 管 Human Insight、Creative Spark 与传播 Idea；Innovation 管产品机会、证据和可测试方向；Proposal 管提案文件的发展与成稿。**


## 版本更新怎么处理

Canonical Source：

> https://github.com/rogerwangzheng1027/civilization-ai-skills

- Project Hub 统一管理版本检查协议；
- 四个 Specialist 继承，不各自维护；
- 发现更新时先说明“当前版本 → 最新版本”及关键变化；
- **不静默覆盖**正在使用的 Skill；
- Skill 本身不能后台每周自动运行；需要主动周检时，用外部 Automation / Scheduler。

## ChatGPT Plugin 的团队安装包

如果你是在 ChatGPT 中通过 Plugin Creator 使用本系统，直接查看 [个人安装说明](./INSTALL_CHATGPT.md)，从 [GitHub Releases](https://github.com/rogerwangzheng1027/civilization-ai-skills/releases) 下载最新的 `civilization-ai-specialists-vX.Y.Z` ZIP。

维护者只需要在 `main` 更新原始 `SKILL.md`（或共享源文件）；GitHub Actions 会自动同步原文并发布新版 ZIP。**不会自动改写原始 Skill，也不会静默更新已经安装的个人 Plugin。** 每位使用者先阅读版本变化，再确认是否更新自己正在使用的插件。
